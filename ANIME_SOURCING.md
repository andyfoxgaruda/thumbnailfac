# Anime asset sourcing

The PhotoCraft MCP server exposes three new tools:

- `source_poster_assets(creative_brief, characters, series, asset_roles, target_width, target_height, minimum_quality, max_candidates_per_role, preferred_visual_style)`: one compact request for verified local artwork. Roles: `foreground`, `secondary`, `background`, `overlay`, `effect`. Returns an asset pack ID, up to four candidates per role, dimensions, provider page, artist if known, score, missing roles, and short diagnostics. Reuse `previous_pack_id` plus `replace_role` to replace one role.
- `load_asset_pack_into_photocraft(pack_id, output_name, choices, width, height, actions_json, preview, job_id)`: imports one chosen asset per role, ordered background to foreground, as editable embedded layers through the existing native bridge. `choices` maps roles to returned asset IDs. The image originals stay intact. `actions_json` uses the existing edit plan syntax and command allowlist.
- `get_anime_source_health()`: persisted search counts, success counts, average latency, current cooldown, and cumulative MCP sourcing response bytes. A fresh server process retains measured history.

The coordinator uses anonymous, read-only public endpoints from [Danbooru](https://safebooru.donmai.us/wiki_pages/help%3Aapi), [Safebooru.org](https://safebooru.org/index.php?page=help&topic=dapi), and Yande.re's live `/post.json` endpoint. The first two have published API documentation. Yande.re's endpoint and response format were verified live; its help page was unavailable during implementation. Konachan returned HTTP 403 and was not integrated. These are separate content sources; no uptime guarantee is implied. Safebooru.org's [terms](https://www.safebooru.org/index.php?page=tos) allow API access without hammering, restrict site use to personal use, and prohibit advertisements or paywalls when serving its API/CDN content. Provider and artwork terms may change. All downloaded artwork is marked `rights: unknown`; source pages and available attribution are retained. A public post does not establish permission to republish it.

Each provider has a conservative one-second spacing between searches. Failures enter exponential cooldown, access denial enters a five-minute cooldown, and these states survive a restart. Search responses are bounded to 12 posts per request, two passes per role. Requests to different healthy providers run concurrently. Downloads use the existing public-IP and redirect checks, then verify actual image decoding, size and dimensions. Exact SHA-256 and 64-bit difference hashes find duplicates. Assets are written atomically to `Assets/Downloaded` with content-based names. Metadata, quality measurements, use counts, provider events, and pack records live in `Logs/anime_sourcing.sqlite3`. Repeating an identical request reuses a complete pack for seven days with no provider calls.

The score combines source tags, role suitability, real resolution, measured edge detail, and transparency. It does **not** perform semantic image recognition. A provider can mis-tag artwork, and a sharp single-character image can still be a poor poster choice. The foreground gate rejects obvious group scenes and scenery, but final visual review remains useful. Backgrounds and effects may return `INSUFFICIENT_QUALITY`; the tool does not fabricate a match. Original art is imported as an image layer, not automatically segmented into a transparent cutout. Use the existing local segmentation tools when a cutout is needed.

The high-level sourcing call returns a few hundred bytes for a cached one-candidate pack, without embedding image previews, raw API JSON, or large tag lists. The first Naruto test after the foreground gate returned a 2894×4093 single-character image; a Death Note test returned a 2893×4092 Light Yagami image. Visual inspection found both character focused. The earlier resolution-only Naruto pick was a group landscape; its failure drove the stricter role gate. Tests live in `tests/test_anime_sourcing.py`. Set `PHOTOCRAFT_RUN_LIVE=1` to run the installed-app gateway regressions in `tests/test_photocraft_gateway.py`.
